# Цифровые двойники цехов: инструкция для Claude

Читай этот файл целиком перед любой работой в папке. Отвечай пользователю по-русски, коротко и по делу.

## Кто пользователь и зачем проект
- Работает с металлургическими и трубными предприятиями России (НЛМК, ММК, ТМК: ЧТПЗ, ПНТЗ, СТЗ; Северсталь, ЕВРАЗ).
- Цель: делать **цифровые двойники цехов** — 3D-модель цеха в реальных габаритах + живая симуляция процесса + расчёт загрузки. Показывать заводам, продавать пилоты.
- Первый готовый образец: **цех эпоксидных порошковых красок (ЭПК)** для изоляции труб (CSA Z245.20, ISO 21809) — это `plant-twin`. Он работает, его надо развивать и копировать на новые цеха.
- Разбор рынка и заводов: `docs/metallurgy-research.md`. Следующая цель: цех **«Высота 239» ЧТПЗ** по открытым данным (план там же).

## Главные правила
1. **Только улучшаем, ничего не ломаем.** Новое делаем отдельными переключателями/режимами; поведение по умолчанию сохраняем. После правки проверяй, что старое работает.
2. **Светлая стилистика** по умолчанию («Схема»: белая макетная модель с графитовыми контурами, светлый интерфейс). Режим «Реалистично» — дополнительный.
3. **Детализация станков важнее всего.** Каждый станок собран из реальных узлов: двигатели IEC, редукторы, рамы, площадки с ограждениями, лестницы, бункеры, затворы, шкафы, сигнальные колонны. Не рисуй «коробки».
4. **Честность данных.** Все цифры либо из источника, либо помечены «допущение — заменить паспортными». Не выдумывай характеристики конкретного завода. Происхождение единицы оборудования помечается: `given` (из схемы/данных завода), `added` (технологически необходимо), `norm` (требуется стандартом).
5. **Экономь токены.** Не переписывай файлы целиком без нужды, правь точечно; не делай лишних проверок и скриншотов; не пересказывай в ответе то, что видно в коде.
6. **Конфиденциальность.** Документы заводов (планировки, паспорта, BIM, облака точек) — под NDA. Храни их в `private/` (в .gitignore), не коммить в публичный репозиторий, не публикуй. Публичные демо — только на открытых данных.
7. Перед коммитом/пушем спрашивай пользователя, если он не просил явно.

## Как запускать
```
npm install          # один раз
npm run dev          # http://localhost:8080 — работа с исходниками (src/)
npm run build        # dist/index.html — один файл для показа (нужен интернет: three.js с CDN)
npm run export:unreal  # export/epk-plant.glb для Unreal/Blender (нужен Playwright + Chromium)
```
Проверка после правок: `npm run build` без ошибок, открыть страницу, консоль браузера без ошибок, основные режимы работают (обзор, выбор станка, прогулка, «Мощность и загрузка»).

## Архитектура (three.js 0.160, без фреймворков)
| Папка | Что внутри |
|---|---|
| `src/core/kit.js` | Геометрический кит `Assembly`: примитивы (box/blk/cyl/lathe/pipe/rod/ring…), сливает детали в один меш на слой + контуры рёбер. Координаты в метрах, Y вверх. |
| `src/core/look.js` | Палитры (`light` = «Схема», `real` = «Реалистично»), наборы материалов по слоям: `body, dark, steel, rubber, glass, product, struct, cladding`. Процедурная фактура `addGrain`. |
| `src/eq/parts.js` | Типовые узлы: `motor, gearbox, cabinet, platform, stair, ladder, handrail, hopper, rotaryValve, legs4, pallet…` — используй их. |
| `src/eq/*.js` | Станки по участкам (process, milling, prep, packing, lab, utilities, actors). Билдер: `function name(eq) { eq.body(a => {...}); eq.light(...); eq.anchor.set(...); eq.update = (st, dt) => {...} }`. |
| `src/eq/equipment.js` | Класс `Equipment`: тело, подвижные части (`eq.part`), сигнальная колонна, статус. |
| `src/plant/layout.js` | **Реестр цеха**: здание `HALL`, оси, зоны `ZONES`, слоты логистики, список `EQUIPMENT` (tag, type, name, model, zone, pos, src, desc, spec, sim). |
| `src/plant/plant.js` | Сборка цеха из реестра + синхронизация 3D с моделью (смесители, погрузчики, люди, поддоны). |
| `src/plant/services.js` | Инженерные сети (аспирация, воздух, вода, пневмотранспорт, лотки). |
| `src/scene/building.js` | Здание: каркас по сетке 6 м, стены, кровля, разметка, оси. |
| `src/sim/model.js` | Дискретная модель процесса (заказы, партии, контейнеры, погрузчики, линии, фасовка, ОТК, отгрузка, смены). `DEFAULTS` — допущения. |
| `src/sim/telemetry.js`, `capacity.js` | Показания по оборудованию; аналитика мощности и узкого места. |
| `src/view/viewer.js` | Рендер, камера, GTAO, выделение, подписи, режимы, качество. |
| `src/view/walk.js` | Прогулка от первого лица (three-mesh-bvh, столкновения, лестницы). |
| `src/ui/ui.js` | Интерфейс: KPI, реестр слева, инспектор справа (сворачиваются), панели вида/режима/картинки/слоёв, вкладка мощности. |
| `src/export/gltf.js` | Экспорт в GLB для Unreal Engine 5 (инструкция `export/README.md`). |

## Как добавить станок
1. Билдер в `src/eq/<участок>.js` из узлов `parts.js`, ось потока — local +X, `side` = сторона обслуживания.
2. Регистрация в `BUILDERS` в `src/plant/plant.js`.
3. Запись в `EQUIPMENT` (`layout.js`): тег по схеме `XX-NNN`, позиция в метрах, паспорт, описание, `src`, привязка к симуляции `sim: { k, i }`.
4. При необходимости статус/показания в `telemetry.js` и логика в `model.js`.

## Как сделать новый цех (например «Высота 239»)
1. Скопировать `plant-twin` → `twin-<имя>` (или вынести общее ядро `core/ view/ ui/` и подключать). Ядро не ломать.
2. Собрать данные (см. `docs/metallurgy-research.md`): габариты корпуса, пролёты, состав и порядок участков, оборудование и производительность. Каждую цифру с источником или пометкой «допущение».
3. Сначала план: зоны и расстановка в `layout.js` → здание в `building.js` → станки по одному, начиная с главных → сети → модель процесса → проверка.
4. Показывать пользователю промежуточный результат после ключевых шагов.
